## СТЕК
Python + pyTelegramBotAPI (telebot) + SQLite. Хостинг: Termux (Android).
Репозиторий: aboraev/NeiborHelp_v2_bot (branch main).

## ФАЙЛЫ
- bot.py — логика бота (~600 строк, 8 блоков сборки)
- database.py — обёртка SQLite (4 блока сборки)
- ~/neighbors_bot.db — база (в HOME, не в репо!)
- ~/.env — BOT_TOKEN, MASTERS_GROUP_ID, ADMIN_ID, GROUP_INVITE_LINK

## СХЕМА БД (sqlite3.Row, доступ по ИМЕНАМ, не по индексам!)
users:    id, user_id, username, role, categories(json),
          rating, rating_count, is_verified
requests: id, user_id, username, text, category, subcategory,
          status, master_id, master_username, timing, contact, created_at

## КРИТИЧЕСКИЕ РЕШЕНИЯ (НЕ ОТКАТЫВАТЬ)
1. SQLite: соединение ВНУТРИ каждой функции, check_same_thread=False,
   conn.close() в finally. Иначе H1: падение процесса на первом же db-запросе.
2. row_factory = sqlite3.Row → dict(res). Никаких req[6]!
3. bot.answer_callback_query(call.id) в КОНЦЕ каждого callback-хендлера,
   включая guard-ветки с return.
4. catch_all на месте (последний хендлер) — лечит "часики" на старых кнопках.
5. SSL-фикс встроен в bot.py (urllib3.disable_warnings + requests verify=False)
   — обязательно, т.к. Termux работает через VPN.
6. user_states.pop(uid) при выходе в home — сброс черновика заявки.
7. Капча: is_verified в БД (не в памяти) — переживает рестарт бота.

  Контакт = request_contact (телефон). Q4 из диагностики ПЕРЕСМОТРЕН:
  у многих соседей нет @username, телефон надёжнее.

МОИ ЗАЯВКИ: 🟢 Активные / ⚪ Архив. Авто-архив заявок new старше 3 дней.
  Заказчик: ✏️ Редактировать / ❌ Отменить (с обязательным комментарием)
  Мастер:   ⚙️ В работу / ✔️ Готово / ❌ Отказаться (с комментарием)
  Внизу: ◀️ Назад + 🏠 Главная.

СТАТУСЫ: new / accepted / in_progress / done / cancelled / archived
ЛИМИТЫ: 3 активные заявки у заказчика, 3 активных заказа у мастера.
ПОДТВЕРЖДЕНИЯ: критические действия (отмена, завершение) — через
  кнопку "Да, ..." + "Назад" (защита от случайного клика).
УВЕДОМЛЕНИЯ: мастеру — при отмене/редактировании заказчиком;
  заказчику — при принятии/старте/отказе мастера.

## МЕТОДОЛОГИЯ РАБОТЫ (что прижилось)
1. Патч-скрипты через str.replace() — НЕ regex (regex ломает \n в строках).
   Шаблон: cat > patch.py << 'EOF' ... content.replace(old, new) ... EOF
   В конце — чек-лист проверок ('X' in content).
2. Бэкап перед патчем: cp bot.py bot_backup_$(date +%Y%m%d_%H%M%S).py
3. Проверка синтаксиса ВСЕГДА после патча:
   python -c "import ast; ast.parse(open('bot.py').read()); print('SYNTAX OK')"
4. Копирование на телефон: блоки по 50-80 строк, heredoc:
   первый блок — cat > file << 'EOF' (создаёт),
   следующие — cat >> file << 'EOF' (дописывают).
   EOF должен быть на отдельной строке без пробелов.
5. Точечная вставка строк: sed -i '20i ...' (для SSL-фикса и т.п.).
6. Развёртывание: файлы в репо → cp bot.py database.py ~/ → python ~/bot.py.
   ВАЖНО: бот импортирует database.py из ~, а не из репо. После git pull
   ОБЯЗАТЕЛЬНО повторять cp.
